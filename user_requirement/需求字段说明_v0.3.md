# 墨灵 UserRequirement 需求字段说明

**版本：v0.3**  
**任务：W02-1**  
**用途：将用户自然语言练字需求整理为统一结构，供后续个性化字帖生成、Training Planner 和 WorksheetPlan 使用。**

> 本版重点明确两件事：
> 1. 哪些字段为 `null` 时需要追问；
> 2. 非法值不能进入 `expected`，而应在 `errors` 中保留原始非法值。

---

## 1. UserRequirement 字段

| 字段 | 类型 | 含义 | 为 `null` 时的处理 |
|---|---|---|---|
| `occupation` | string / null | 用户明确表达的职业或身份，如教师、学生、护士 | 单独为 `null` 时暂时不用追问 |
| `scene` | string / null | 用户明确表达的书写场景，如课堂板书、作业、病历书写 | 单独为 `null` 时暂时不用追问 |
| `style` | enum / null | 用户要求练习的书体 | **必须追问** |
| `duration_minutes` | integer / null | 单次练习时长，单位为分钟 | **必须追问** |
| `goal` | string / null | 用户明确表达的练习目标，如改善工整度 | 单独为 `null` 时暂时不用追问 |
| `exclusions` | string[] | 用户明确要求排除的内容或条件 | 没有排除项时使用 `[]`，不追问 |

---

## 2. 个性化字帖生成的追问规则

判断标准不是“字段是否全部填写”，而是：

> **当前信息是否已经足够生成一份满足用户需求的个性化字帖。**

### 2.1 必须追问的字段

以下字段为 `null` 时，必须追问：

- `style`
- `duration_minutes`

原因：

- 没有 `style`，无法确定字帖采用什么书体；
- 没有 `duration_minutes`，无法确定本次训练量和训练计划。

### 2.2 可以暂时为 `null` 的字段

以下字段单独为 `null` 时，不阻塞 Workplan：

- `occupation`
- `scene`
- `goal`

它们主要用于提高字帖的个性化程度。

例如：

```text
楷书 + 15分钟 + 教师
```

虽然 `scene` 和 `goal` 都是 `null`，仍然可以生成。

又如：

```text
楷书 + 15分钟 + 课堂板书
```

虽然 `occupation` 和 `goal` 都是 `null`，仍然可以生成。

### 2.3 特殊情况：个性化信息全部缺失

如果：

```text
occupation = null
scene = null
goal = null
```

则需要追问一次。

因为此时只有：

```text
style + duration
```

系统只能生成比较通用的字帖，缺少个性化方向。

建议追问：

> “你主要想把练字用在哪种场景，或者希望改善什么？比如日常书写、学习、工作，或者字迹工整度。”

### 2.4 exclusions

`exclusions` 不作为 Workplan 的启动条件。

用户没有提出排除要求时：

```json
"exclusions": []
```

不需要追问。

---

## 3. Workplan 生成前置条件

满足以下条件，才允许进入 Workplan：

```text
① style != null
② duration_minutes != null
③ occupation / scene / goal 至少一个 != null
```

判断逻辑：

```python
if style is None:
    needs_clarification("style")

elif duration_minutes is None:
    needs_clarification("duration_minutes")

elif occupation is None and scene is None and goal is None:
    needs_clarification("occupation_or_scene_or_goal")

else:
    generate_workplan()
```

---

## 4. null、非法值与错误信息的区别

这是本版新增的重点规则。

### 4.1 null 表示“用户没有提供”

例如：

> “我是老师，每天练15分钟。”

用户没有说书体，因此：

```json
"style": null
```

此时 `status` 为：

```text
needs_clarification
```

### 4.2 非法值不能进入 expected

例如：

> “我是学生，每天练-10分钟，想练楷书。”

`duration_minutes` 的合法范围为：

```text
>= 1
```

所以 `-10` 是非法值。

**最终 `expected` 中不能写：**

```json
"duration_minutes": -10
```

而应该写：

```json
"duration_minutes": null
```

原始非法值写入：

```json
"errors": [
  {
    "type": "invalid_value",
    "field": "duration_minutes",
    "value": -10
  }
]
```

统一规则：

> **字段值通过校验 → 写入 `expected`；字段值未通过校验 → `expected` 中该字段置为 `null`，原始非法值写入 `errors`。**

### 4.3 不支持的书体同理

例如用户说：

> “我是老师，平时写课堂板书，每天15分钟，想练草书。”

如果 v0 只支持：

```text
楷书
行书
行楷
```

那么：

```json
"style": null
```

并在 `errors` 中保留：

```json
{
  "type": "unsupported_style_value",
  "field": "style",
  "value": "草书"
}
```

## 5. 状态字段

解析结果包含：

- `status`
- `follow_up`
- `errors`

### complete

已经满足 Workplan 最低生成条件，没有冲突或非法值。

### needs_clarification

缺少生成所需的信息，需要向用户追问。

### conflict

用户意愿明确，但与当前系统能力或其他约束发生冲突。

例如用户想练行书，而当前系统只支持楷书。

处理原则：

1. 保留用户原始意愿；
2. 标记 `conflict`；
3. 通过 `follow_up` 让用户确认替代方案。

### invalid

用户提供的值违反字段定义或合法范围。

例如：

```text
duration_minutes = -10
```

处理原则：

1. `expected` 中对应字段置为 `null`；
2. `errors` 保存原始非法值；
3. `follow_up` 要求用户重新提供合法值。

---

## 6. 书体规则

v0 暂定支持：

- `楷书`
- `行书`
- `行楷`

注意区分：

> **用户意愿** 与 **系统当前支持能力**。

例如：

> “我想练行书，但目前系统只支持楷书。”

用户意愿是“行书”，因此不能静默改成“楷书”。

如果此处按“冲突”处理：

```json
"style": "行书",
"status": "conflict"
```

再通过 `follow_up` 让用户决定是否改用楷书。

---

## 7. 练习时长规则

当前项目第 2 周保底协议为：

- 5 分钟
- 15 分钟
- 30 分钟

如果用户明确提出其他正整数，例如“每天20分钟”，W02-1 保留用户表达：

```json
"duration_minutes": 20
```

是否在 Planner 阶段映射到 5/15/30 分钟，由后续任务决定。

如果时长缺失：

```json
"duration_minutes": null
```

并：

```text
status = needs_clarification
```

不能擅自默认成 15 分钟。

如果时长非法，例如 `-10`：

```json
"duration_minutes": null
```

并将 `-10` 保存到 `errors`。

---

## 8. 不允许模型自行推断

以下信息不能从常识中补出来：

- 没说职业，不能因为“板书”就自动填写“教师”；
- 没说场景，不能因为职业是教师就自动填写“课堂板书”；
- 没说目标，不能自动填写“提高书写水平”；
- 没说时长，不能自动填写15分钟；
- 没说书体，不能自动选择楷书。

**默认值和用户明确表达必须区分。**

---

## 9. 别名规范化

v0 只做明确、可靠的别名映射：

- “老师” → “教师”
- “小学生” → “学生”
- “楷体” → “楷书”
- “行楷体” → “行楷”

不能因为语义相近就擅自推断用户没有表达的信息。

---

## 10. 追问优先级

如果同时缺少多个信息，建议按以下顺序追问：

### 第一优先级：style

```text
style = null
```

> 必须追问。

### 第二优先级：duration_minutes

```text
duration_minutes = null
```

> 必须追问。

### 第三优先级：个性化维度

如果：

```text
occupation = null
scene = null
goal = null
```

> 追问用户的使用场景或练习目标。

如果三者至少一个已有值：

> 暂时不用追问，可以进入 Workplan。

## 11. 典型判断示例

| style | duration | occupation | scene | goal | 是否追问 |
|---|---:|---|---|---|---|
| 楷书 | 15 | 教师 | null | null | 否 |
| 楷书 | 15 | null | 课堂板书 | null | 否 |
| 楷书 | 15 | null | null | 改善工整度 | 否 |
| 楷书 | 15 | null | null | null | **是** |
| null | 15 | 教师 | null | null | **是** |
| 楷书 | null | 教师 | null | null | **是** |

---

## 12. 验收标准

- 10 组样例覆盖正常、缺失、冲突、非法输入；
- `style = null` 时必须追问；
- `duration_minutes = null` 时必须追问；
- `occupation / scene / goal` 单独为 `null` 时暂时不用追问；
- `occupation / scene / goal` 全部为 `null` 时需要追问；
- `exclusions` 没有排除项时为 `[]`；
- 非法字段不能把非法值放入 `expected`；
- 非法原始值必须保存在 `errors` 中；
- `null` 表示用户没有提供该信息；
- 不允许模型从用户原话之外自行补充职业、场景、目标、书体或时长。

---

## 13. 未决问题

以下内容交由后续任务确认：

1. 最终实际支持哪些书体，需要与工程侧能力确认。
2. 5/15/30 分钟之外的时长如何处理，由 Planner 决定。
3. 只有职业没有场景时，如何检索职业相关高频字词，由后续内容检索设计决定。
4. 只有目标没有职业/场景时，如何选择训练字词，由后续 Planner 设计决定。
