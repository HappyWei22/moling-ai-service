# 墨灵 UserRequirement 需求字段说明

**版本：v0.1**\
**任务：W02-1**\
**用途：将用户自然语言练字需求整理为统一结构，供后续职业/场景检索、Training
Planner 和 WorksheetPlan 使用。**

> 本版严格遵循当前第2周计划：先保住教师/学生场景、支持书体和 5/15/30
> 分钟协议；不自行扩展复杂多轮记忆。申报书明确的平台入口是"自然语言需求→智能分析→字帖生成"，用户可描述职业类型、常用字、书写场景等需求。

## 2. 状态字段

解析结果额外包含：

-   `status`：`complete`、`needs_clarification`、`conflict`、`invalid`
-   `follow_up`：需要用户补充或确认时的追问；不需要追问时为 `null`
-   `errors`：校验或业务错误列表；无错误时为 `[]`

### 状态含义

-   `complete`：信息足够且没有发现冲突/非法值。
-   `needs_clarification`：存在关键缺失信息，需要追问；不能自行编造。
-   `conflict`：用户意愿与当前系统能力或约束冲突；保留用户原始意愿，不静默替换。
-   `invalid`：输入值违反字段格式/合法范围，例如负数练习时长。

## 3. 书体规则

v0 先覆盖项目范围内的 `楷书`、`行书`、`行楷`。

注意：**"用户想练什么"与"系统当前支持什么"是两个概念。**

例如：

> 想练行书，但目前系统只支持楷书。

应记录：

``` json
"style": "行书"
```

然后标记 `conflict`，不能直接把用户需求改成：

``` json
"style": "楷书"
```

这样会丢失用户原始意愿。

## 4. 练习时长规则

当前第2周保底协议为：

-   5 分钟
-   15 分钟
-   30 分钟

如果用户明确说出其他正整数时长，例如"每天20分钟"，W02-1
应保留用户输入，不擅自改成15或30；是否允许 Planner 接受该时长由 W02-3
决定。

如果出现非正数、无法解析的时长，应标记为 `invalid`。

## 5. 缺失与冲突必须区分

### 缺失

"我是老师，每天15分钟。"

能够确定：

-   occupation = 教师
-   duration_minutes = 15

不能确定：

-   scene
-   style
-   goal

所以未知字段为 `null`，状态为 `needs_clarification`。

### 冲突

"我想练行书，但目前系统只支持楷书。"

用户需求是明确的，但与系统能力发生冲突。

所以：

1.  保留 `style = 行书`
2.  状态 = `conflict`
3.  通过 `follow_up` 请用户确认替代方案

## 6. 不允许模型自行推断

以下信息不能从常识中"脑补"：

-   用户没有说"教师"，不能因为"板书"就自动填写教师。
-   用户没有说"行书"，不能因为是职场人士就自动填写行书。
-   用户没有说练习目标，不能自动填写"提高书写水平"。
-   用户没有说时长，不能自动填写15分钟。

**默认值和用户明确表达必须可以区分。**

## 7. 别名与规范化

v0 只做最小规范化，不改变用户意图。

示例：

-   "老师" → "教师"
-   "小学生" → "学生"
-   "楷体/楷书" → "楷书"（正式别名表仍需后续确认）
-   "行楷体/行楷" → "行楷"

如果一个词无法可靠映射到规范值，不应强行归类，应保留原文或进入追问。

## 8. 追问触发条件

优先追问会影响后续字帖生成的关键字段：

1.  缺少 `style`，且当前场景必须确定书体；
2.  缺少 `scene`，且职业/场景定制是生成内容的重要依据；
3.  缺少 `duration_minutes`，且规划阶段需要时长；
4.  出现 `conflict`；
5.  出现 `invalid`。

追问应该一次解决尽可能少但关键的信息，不要一次提出大量无关问题。

## 9. 典型追问

-   缺少书体：`你想练楷书、行书还是行楷？`
-   缺少场景：`你主要在哪种场景使用这套字帖，例如课堂板书、作业还是日常书写？`
-   缺少时长：`你每次大约想练几分钟？目前可以按5、15或30分钟来规划。`
-   发生书体冲突：`你希望练行书，但当前版本支持的书体需要以系统实际配置为准。是否先改用楷书？`

## 10. 验收标准

本版完成后应满足：

-   10组样例全部有人工期望结果；
-   覆盖正常、缺失、冲突、非法输入；
-   不从用户原话之外补职业、书体、目标等信息；
-   `null` 表示未知，`[]` 表示没有排除项；
-   默认值与用户明确表达可以区分；
-   下游可以读取固定字段；
-   非法值或冲突不能静默进入后续规划。

## 11. 未决问题

以下内容不在 W02-1 中擅自决定，交给后续任务确认：

1.  系统最终实际支持哪些书体，需要与 W02-4 的模型/前后端能力核对。
2.  5/15/30 分钟之外的时长是否需要自动映射到最近档位，由 W02-3 决定。
3.  更复杂的多轮记忆和用户长期画像不在本 v0 范围内。
