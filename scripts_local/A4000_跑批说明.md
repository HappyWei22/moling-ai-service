# 在 A4000 那台 Windows 机器上复跑 v2 评测集

> 目标机器：**Xeon W-2223（4 核 8 线程）/ 128 GB RAM / RTX A4000 16 GB / Windows**
> 评测集、提示词、评分代码全部不变，只换模型与硬件 → 结果可与云端 qwen3.8-flash 直接对比。

## 0. 一句话结论先摆着

**首选 `qwen2.5:14b-instruct-q4_k_m`（约 9 GB）。** 16 GB 显存能全量上卡，这是这套配置相对那台 8 GB 笔记本唯一实质性的提升。32B 不要碰——4 核 Xeon 一旦 offload 会慢到没法迭代。

## 1. 先自检，不要直接跑

把仓库放到目标机器后，**第一件事**是运行自检脚本。它会一次性报出 6 类问题，最后直接打印可复制的跑批命令。

```powershell
cd <仓库目录>
powershell -ExecutionPolicy Bypass -File scripts_local\windows_check.ps1
```

指定别的模型或别的解释器：

```powershell
powershell -ExecutionPolicy Bypass -File scripts_local\windows_check.ps1 -Model qwen2.5:14b-instruct-q4_k_m -Python "C:\Python312\python.exe"
```

## 2. 装 Ollama（Windows 版，一次性）

1. 下载 `OllamaSetup.exe`：<https://ollama.com/download/windows>
   （有 winget 也可以：`winget install --id Ollama.Ollama -e`）
2. 双击安装。**装完是托盘应用，会自动启动并在 11434 监听，不要手动 `ollama serve`**——会报端口占用。
3. **装完必须新开一个终端**，否则 `ollama` 还不在 PATH 里。老版本装在 `%LOCALAPPDATA%\Programs\Ollama\`，自检脚本会自动去这个目录找。
4. 验证：

```powershell
nvidia-smi
ollama --version
ollama list
```

拉模型（约 8.6 GB，看网速 5–30 分钟）：

```powershell
ollama pull qwen2.5:14b-instruct-q4_k_m
```

> 名字以 `ollama list` 实际输出为准。备选 `qwen3:14b`（要额外关 thinking，见 §6），`qwen3:30b-a3b`（MoE，能摸到 30B，但会部分 offload）。

**内网隔离 / 不让连外网**：见 §8 离线搬运。

## 3. 拿代码

```powershell
git clone -b feat/v2-eval-set https://github.com/HappyWei22/moling-ai-service.git moling-repo
cd moling-repo
python -m pip install -r requirements.txt
```

> `scripts_local\` **还没提交进仓库**（本地开发用）。克隆下来如果没有这个目录，从开发机把它整个拷过来。里面 6 个文件缺一不可：
> `run_local_ollama.py`、`_device.py`、`windows_check.ps1`、`bench_local_models.py`、两份 `.md` 说明。
>
> **省事办法**：开发机桌面上已打好 `moling_local_runner.zip`（23 KB），拷过去解压到仓库根目录，就是 `scripts_local\` 目录。

**跑批只需要 `pydantic`**，`fastapi` / `uvicorn` 是服务端用的。所以 `pip install pydantic` 也够。

## 4. 跑（一条命令，单行粘贴）

```powershell
python scripts_local\run_local_ollama.py --model qwen2.5:14b-instruct-q4_k_m --protocol v2 --samples v2_eval\samples_v2.jsonl --splits dev,val --out v2_eval\baseline\local_qwen25_14b_runs.jsonl --report v2_eval\baseline\local_qwen25_14b_report.md --tag local-qwen25-14b
```

> **PowerShell 的续行符是反引号 `` ` ``，不是 `\`。** 用 `\` 会直接把参数当新命令执行，症状是「命令没报错但什么都没跑」。所以上面故意写成单行，别自行折行。

如果 Ollama 不在本机（例如放在隔壁那台 GPU 机器上，从自己电脑连过去跑）：

```powershell
$env:MOLING_OLLAMA_BASE = "http://<那台机器IP>:11434/v1"
```

并在那台机器上设 `OLLAMA_HOST=0.0.0.0:11434` 后重启 Ollama。**默认不用管这条**，本机跑就保持默认。

预期：98 条，14B 全量上卡时约 **25–40 tok/s**，全批 **3–6 分钟**（7B 在 4060 上是 1m38s，14B 大约 3 倍）。

跑完会打印：

```text
[local] 硬件：CPU 8 线程 / RAM 128.0 GB / GPU NVIDIA RTX A4000, 16376 MiB, 552.xx
[local] 硬件快照已写入：v2_eval\baseline\local_qwen25_14b_runs.device.json
```

## 5. 跑完必须先核这四项，缺一项数据就不可比

```powershell
python -c "import json;r=json.loads(open(r'v2_eval\baseline\local_qwen25_14b_runs.jsonl',encoding='utf-8').readline());print('model      :',r['model']);print('prompt_sha :',r['prompt_sha256'][:12]);print('samples_sha:',r['samples_sha256'][:12]);print('client     :',r['client'])"
```

| 字段 | 必须是 | 不对说明什么 |
|---|---|---|
| `model` | `qwen2.5:14b-instruct-q4_k_m` | 拉错模型了 |
| `prompt_sha256` 前 12 位 | `97664f29304a` | 提示词被改过，与云端批次不同源 |
| `samples_sha256` 前 12 位 | `b1c1f82a0bfe` | 样本文件不对（分支错 / 被改） |
| `client` | `real` | 没真调模型（走了 mock） |

> ⚠️ 上一轮踩过：脚本打印"提示词覆盖成功"，但实际没生效，`prompt_sha256` 还是旧的。**只认 sha，不认打印。**

## 6. 如果要用 Qwen3 系列

Qwen3 默认开 thinking，会把内容挤进 `reasoning_content` 导致 `content` 为空，v2 的 JSON 解析直接失败。改 `run_local_ollama.py` 的 `build_payload`：

```python
def build_payload(self, system_prompt: str, user_text: str) -> dict:
    payload = super().build_payload(system_prompt, user_text)
    payload["think"] = False        # Ollama 的 OpenAI 兼容层认这个字段
    return payload
```

**先跑 3 条确认 `raw_text` 是纯 JSON 再跑全量**：

```powershell
python scripts_local\run_local_ollama.py --model qwen3:14b --protocol v2 --samples v2_eval\samples_v2.jsonl --splits dev --limit 3 --out .workbuddy_tmp\smoke.jsonl --tag smoke
python -c "import json;[print(json.loads(l)['raw_text'][:120]) for l in open(r'.workbuddy_tmp\smoke.jsonl',encoding='utf-8')]"
```

## 7. 确认模型真的全在显卡上

**这是 4 核机器上最该盯的一项。** 开一个窗口跑批，另一个窗口看：

```powershell
ollama ps
nvidia-smi --query-gpu=memory.used,memory.total --format=csv
```

`ollama ps` 的 `PROCESSOR` 列：

| 显示 | 含义 | 处理 |
|---|---|---|
| `100% GPU` | 全量上卡 | ✅ 正常，直接用 |
| `xx%/yy% CPU/GPU` | 有层跑到 CPU 了 | 降上下文（`OLLAMA_CONTEXT_LENGTH=4096`）或换 `q4_K_S` |
| `100% CPU` | 完全没吃到显卡 | 驱动/CUDA 问题，`nvidia-smi` 先确认卡在 |

`OLLAMA_CONTEXT_LENGTH` 在**启动 Ollama 前**设成系统环境变量再重启托盘程序，改完跑批前用 `ollama ps` 复核。

## 8. 内网隔离：怎么离线搬（很可能是这种情况）

要搬三样，缺一样都跑不起来：

**① Ollama 安装包**
在有网机器下 `OllamaSetup.exe`，拷过去装。

**② 模型文件**——在**有网且已 `ollama pull` 过**的机器上：

```powershell
# 确认模型在位
ollama list
# 整个 models 目录打包（blobs + manifests 都在里面，少一个都不认）
Compress-Archive -Path "$env:USERPROFILE\.ollama\models" -DestinationPath D:\ollama-models.zip
```

到目标机器：

```powershell
# 解到默认位置（目录必须是 models，里面直接是 blobs / manifests）
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ollama" | Out-Null
Expand-Archive -Path D:\ollama-models.zip -DestinationPath "$env:USERPROFILE\.ollama"
ollama list        # 应该能看到那个模型
```

> 若想放 D 盘：先 `setx OLLAMA_MODELS "D:\ollama\models"`，**重启 Ollama 托盘程序**，再把 `models` 目录放到那儿。注意 `setx` 只对新开的终端/新进程生效。

**③ Python 依赖 wheel**

```powershell
# 有网机器
python -m pip download -d wheels -r requirements.txt
# 目标机器
python -m pip install --no-index --find-links wheels -r requirements.txt
```

## 9. Windows 上几个会咬人的点

| 现象 | 原因 / 处理 |
|---|---|
| `ollama` 不是内部或外部命令 | 装完没新开终端，PATH 未刷新 |
| `ollama serve` 报 `bind: Only one usage of each socket address` | 托盘已在跑，**不需要**再 serve |
| 日志中文乱码或 `UnicodeEncodeError` | 跑批前 `$env:PYTHONUTF8="1"`；本机脚本已默认设好 |
| `nvidia-smi` 找不到 | 老驱动在 `C:\Program Files\NVIDIA Corporation\NVSMI\`；`_device.py` 已加这条 fallback |
| 首次加载特别久（几十秒） | Defender 实时扫描在读 9 GB 权重。可把模型目录加排除项，或首次跑前先手动 `ollama run` 预热一次 |
| 跑到一半停了 | 电源计划把睡眠打开了。跑批前设「从不睡眠」，并关闭屏幕保护 |
| 复制命令后「什么都没发生」 | 用了 `\` 续行。PowerShell 用反引号，或者整条写成一行 |
| 结果里 `prompt_sha256` 不是 `97664f29` | 提示词路径覆盖没生效。这是已知坑，以 sha 为准，别信打印 |
| 莫名其妙的 `FileNotFoundError` / 编码报错 | 仓库路径里带中文。**放到纯英文路径**，如 `D:\moling-repo`，别放 `C:\Users\张三\桌面\...` |
| `ollama pull` 报 `manifest unknown` | tag 大小写。试 `qwen2.5:14b-instruct-q4_K_M`（大写 K、M），或先 `ollama pull qwen2.5:14b` 再用 `ollama list` 看真实名字 |

## 10. 结果怎么读

跑完和 `v2_eval\baseline\本地模型对照报告_qwen25-7B.md` 的表格对齐，重点看四个数：

| 指标 | 7B（笔记本 4060） | 14B（A4000，待测） | 云端 qwen3.8-flash |
|---|---|---|---|
| 全一致 | 22/98 (22.4%) | ? | 47/98 (48.0%) |
| 问题集合一致 | 73/98 (74.5%) | ? | 76/98 (77.6%) |
| **错误放行** | **5/71 (7.0%)** | ? | **0/71 (0.0%)** |
| scene 准确 | 58/98 (59.2%) | ? | 84/98 (85.7%) |

**判据**：`错误放行` 不为 0 就不能替代云端；`scene` 到 80% 以上才算补上 7B 的主要短板；全一致到 40% 以上才算接近云端水平。

## 11. 三个必须跟组长讲清楚的点

1. **之前那份 22.4% 不是这台机器跑的**，是笔记本上 7B 的成绩，不能当作 A4000 的预期。两批都已经补了 `*.device.json` 硬件快照，来源可查。
2. **云端基线里混着 E9**（五字段齐全仍返回 `needs_clarification`）8 条。本地模型遵循度弱，反而有 5 条"误打误撞"判对（D001/V003/D004/D062/D064）。所以本地分数里有一部分是云端被已知缺陷拖累的，**不能直接说"本地差一半"**。
3. **提示词一改，`prompt_sha256` 就变**，与云端批次不再同源。任何 prompt 调整都必须单独成批、单独写 sha，不能和 98 条基线混在一起比。
