# 墨灵 v2 需求解析 标注指南

适用协议：`POST /parse/v2`（`parsing/prompt_v2.md` + `parsing/parse_requirement_v2.py`）
本指南为本次评测集标准答案的唯一口径来源；与 v1 标注指南冲突时以本指南为准。

---

## 1. 字段定义

最终需求对象只含五个字段（`schemas.ParsedRequirementV2`）：

| 字段 | 含义 | 取值 |
|---|---|---|
| `occupation` | 职业/身份 | 自由文本；`老师`→`教师`，`小学生`→`学生` |
| `scene` | 书写场景 | 自由文本，**按用户原话保留**，不做等价映射 |
| `font` | 书体名（不是字体文件名） | `楷书` / `行书` / `行楷` / `null`；`楷体`→`楷书`，`行楷体`→`行楷` |
| `duration_minutes` | 单次练习分钟数 | `5` / `15` / `30` / `null` |
| `status` | 最终状态 | `complete` / `needs_clarification` / `conflict` / `invalid` |

**不得输出** `goal`、`exclusions`、`style`、`follow_up` —— 均为 v1 遗留字段。

---

## 2. 三层结果必须分清

标注与判分涉及三层，不要混用：

1. **模型原始输出**：六字段 `{occupation, scene, font, duration_minutes, status, errors}`。模型只负责提取字段、识别非法值与冲突；**不生成追问**，缺失项不由模型报告。
2. **本地最终结果**：`_finalize_v2` 归一化字段、合并问题、去重、裁定状态、生成追问。问题集合存于 `expected_issues`，但**不是**对外需求对象的字段。
3. **API 对外响应**：完整 → `code=0, message="ok", data=五字段对象`；未完成 → `code=400, data=null`。HTTP 均为 200。

> 未完成时对外 `data=null`，字段与内部状态须直接取解析函数结果，**不能从 API 的 `data` 读**，也不能把业务 `code=400` 当成 HTTP 400。

---

## 3. 核心判定规则

1. **完成条件**：`font` 合法且非空、`duration_minutes` ∈ {5,15,30}、`occupation` 或 `scene` 至少一项非空，**且无任何问题**。
2. **未提供必需信息** → `missing_field`。职业与场景**都空**时，字段标 `personalization`，**只算一个问题**。
3. **明确不支持的书体或时长** → 该字段置空，记 `invalid_value`，保留原值证据。
4. **同时要求互相冲突的合法值** → 该字段置空，记 `conflicting_values`，**不得自行挑选一个**。
5. **状态裁定**：`invalid > conflict > needs_clarification`；无问题才 `complete`。状态只有一个，问题可有多个。
6. **同字段已非法/冲突时，不再追加该字段的缺失问题**。同类同字段问题去重，不同字段的问题不得丢失。
7. **多轮**：后续回答可补充或**明确修正**先前回答。「改成」「刚才说错了」属修正，不判冲突；单纯同时要两个值也不机械采用最后一个。

---

## 4. 归一化规则

| 类别 | 规则 | 例 |
|---|---|---|
| 职业 | `老师`→`教师`；`小学生`→`学生` | 「我是个当老师的」→ `教师` |
| 书体 | `楷体`→`楷书`；`行楷体`→`行楷` | 「练楷体」→ `楷书` |
| 时长 | 中文数字与单位换算 | `十五分钟`→15；`半小时`→30；`五分钟`→5 |
| 时长（换算后非档位） | **仍为非法值**，不静默映射到最近档位 | `1小时`→60 非法；`两小时`→120 非法 |
| 场景 | 保留用户原话，不做等价改写 | 「写板书」不改为「教学板书」 |

### 4.1 不取端点的表达（重点）

| 表达 | 处理 |
|---|---|
| `大概20分钟左右` | `invalid_value`，**不得取 20** |
| `15到20分钟` | `invalid_value`，**不得取 15 或 20** |
| `一会儿` / `一小会儿` | `missing_field`（无明确数值） |
| `每天练3次` | 3 是次数不是时长 → 时长仍缺失 |

### 4.2 不支持的书写相关词

`草书`、`篆书`、`隶书`、`瘦金体`、`狂草`、`毛笔字` → 全部 `invalid_value`，`field=font`。
注意 `毛笔字` 是**书写工具**不是书体名。

---

## 5. 问题类型与字段取值

`expected_issues[*].type` ∈ {`missing_field`, `invalid_value`, `conflicting_values`}
`expected_issues[*].field` ∈ {`occupation`, `scene`, `font`, `duration_minutes`, `personalization`}

同一 `(type, field)` **不得重复**。

**问题排序**（与实现一致，便于核对）：`font` → `duration_minutes` → `occupation` → `scene` → `personalization`。

---

## 6. 原值（`value`）的写法

- `missing_field` 的 `value` 恒为 `null`。
- `invalid_value` / `conflicting_values` 的 `value` 取**用户原话片段**或**模型原值**，须能在 `input` 中找到或由 `input` 推出。
- 本集**全部使用原话精确值**，未使用等价表达。若后续允许等价表达（如 `-10` 与 `负十分钟`），必须**同步扩展评分规则**后再放开，不能仅在文档中声明放行。

---

## 7. 多轮样本

- 同一会话的每个检查点单独一条记录；记录 `conversation_id`、`turn_index`、`user_turns`，以及 `input`（= 截至当前轮的**合并**用户原话）。
- `input` **只包含截至当前轮的内容**，不得把未来回答提前放入。
- 同一会话的所有检查点必须在**同一分集**；`semantic_group` 亦然。
- 统计时同时报告输入条数、独立会话数、语义组数，不得把多轮检查点算成独立用户。

---

## 8. 分集纪律

1. 同义改写、近重复、同一会话各轮检查点必须进**同一分集**；同一 `semantic_group` 不得跨集。
2. `dev` 用于调试与修复；`val` 用于阶段验证；`sealed` 只用于冻结后最终评估。
3. `sealed` 至少覆盖完整、缺失、非法、冲突、多问题组合、多轮场景。
4. 新 `sealed` 优先使用**独立新建**语义组，不使用已拿来调提示词、讨论失败或展示示例的内容。
5. 冻结后不得用 `sealed` 挑错、改提示词或反复试跑。同一冻结版本最终整批评估一次。
6. 样本包版本、协议版本、模型版本**分别记录**；不覆盖旧 v1 样本与历史结果。

---

## 9. 已知上游行为（E8）——影响冲突样本标注

`parsing/parse_requirement_v2.py::_collect_errors` 会对 `font`/`duration_minutes` 的**候选原值**做本地枚举校验。
冲突原话（如「楷书和行书」）本身不是合法枚举值，因此会被**额外**补一条 `invalid_value`。

**后果**：纯冲突输入的最终状态是 `invalid`，**不是** `conflict`；`conflict` 在 v2 实际不可达。

**本集处理**：如实记录真实行为，冲突字段同时带 `conflicting_values` 与 `invalid_value`，`status=invalid`。
追问会出现两条自相矛盾的消息（先说冲突，再说「不在支持范围内」）。详见 `争议裁决表.md` D01。

> **标注提醒**：不要凭任务说明 §3.2 的字面把纯冲突标成 `conflict` —— 那会导致自动校验失败，
> 因为脚本用 `invalid > conflict > needs_clarification` 从**问题集合**反推状态。

---

## 10. 追问（`message`）复核口径

- 追问由**本地**生成，模型不输出 `follow_up`。
- 一次汇总**全部**已识别问题，用编号列表；单问题不加编号。
- 非法/冲突字段**不得**再被当作缺失重复追问。
- 职业与场景**都空**时只问一条组合问题（「你是什么职业，或者主要在哪种场景使用书写？」），
  **不分别强制补职业和场景**，也不以目标替代两者。
- `message_check.required` / `forbidden` 是**人工语义复核**要求，脚本只原样保存、不做子串匹配。
  需要机器检查时另用 `contains` / `not_contains`。
- 自动满足但追问未复核的样本，`end_to_end_match=null`、`message_review=pending`，
  **不得按端到端成功计分**。

---

## 11. 每条样本的字段清单

```jsonc
{
  "id": "V2-D001", "protocol_version": "v2", "split": "dev",
  "semantic_group": "V2-G001", "tags": ["complete"],
  "input": "...", "conversation_id": null, "turn_index": null,
  "user_turns": ["..."],
  "source": {"kind": "new|migrated", "v1_id": null},
  "expected_requirement": { /* 五字段 */ },
  "expected_model_errors": [ /* 只含非法/冲突 */ ],
  "expected_issues": [ /* 含本地补齐的完整问题集合 */ ],
  "expected_api": {"http_status": 200, "code": 400, "data": null},
  "message_check": {"required": [...], "forbidden": [...]},
  "rationale": "...", "evidence": {...},
  "annotator": "...", "reviewer": "..."
}
```

`expected_model_errors` 必须等于 `expected_issues` 中**非 `missing_field`** 的项（顺序不计）。
