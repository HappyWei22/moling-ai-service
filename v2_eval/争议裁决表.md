## D01 · 冲突字段的候选原值非法时，状态从 conflict 被降级为 invalid（上游缺陷 E8）

| 项 | 内容 |
|---|---|
| 现象 | 「两个合法值并列」的纯冲突输入（如 `楷书和行书，每次15分钟。`），最终状态是 `invalid` 而非 `conflict`。 |
| 最小复现 | 候选 `{font:"楷书和行书", duration_minutes:15, status:"conflict", errors:[{type:"conflicting_values", field:"font", value:"楷书和行书"}]}` → 实得 `status="invalid"`，问题集合含 `conflicting_values/font` + `invalid_value/font`。 |
| 根因 | `parsing/parse_requirement_v2.py::_collect_errors` 第 63—67 行：对 `font`/`duration_minutes` 的**候选原值**做本地枚举校验。冲突原话（如「楷书和行书」）本身不是合法枚举值，于是被**额外**补一条 `invalid_value`。随后 `_finalize_v2` 按 `invalid > conflict > needs_clarification` 裁定时，因存在 `invalid_value` 而降级为 `invalid`。 |
| 影响 | ① 冲突字段的**候选原值非法**时，`conflict` 被降级为 `invalid`，与任务说明 §3.2「有冲突为 conflict」及 §4.1 优先级规则不符；② 追问消息出现**自相矛盾**的两条：先说「书体存在冲突，请确认本次以哪个为准」，紧接着说「书体不在支持范围内（你提供的是楷书和行书）」——但用户提供的两个书体都是**受支持**的。③ 影响本数据集 22 条冲突样本中的 **9 条**。 |
| 候选解释 A | 属上游缺陷，应修：冲突字段已报 `conflicting_values` 时不再补 `invalid_value`，使该字段的 `conflict` 可达。 |
| 候选解释 B | 属预期行为：把「无法唯一确定的书体原值」一律视为非法值，`conflict` 仅用于其他场景。 |
| **裁决** | **按候选解释 A 认定为上游缺陷（登记编号 E8）**，但**本次不修改仓库源码**：本任务是建评测集，改公共解析代码会影响其他成员的 v2 基线与其他人的评估结果。 |
| 落地方式 | 样本标准答案**如实记录真实代码行为**（候选原值非法时 → `invalid`，问题集合含成对的 `conflicting_values` + `invalid_value`），使评测集可复现、可判分。缺陷本身登记在此并附最小修复方案（见下）。 |
| 复核要点 | 若上游按 A 修复，本数据集受影响样本的 `expected_requirement.status` 与 `expected_issues` 需同步重标，并更新 `split_manifest.json` 与本表；不得在未重标的情况下直接沿用。 |

> **2026-10-09 修正（依据真实批次 `20261009T145849Z-v2-baseline`）**
>
> 建集初稿曾把 E8 描述为「**`conflict` 状态完全不可达**」。**该说法不准确，现予更正。**
> 真实模型批次（98 条）显示：模型有 10 次正确输出 `conflict`，其中当冲突字段的候选值
> **本身是合法枚举值**时（如 `font="楷书"` 配 `conflicting_values` 声明），
> 最终状态**正常保留为 `conflict`**，未被降级。
>
> E8 的**真实边界**是：**仅当冲突字段的候选原值是非法枚举值时**，该字段才被降级为 `invalid`。
> 已用上游真代码双向复现验证：
>
> | 候选 | 最终 status |
> |---|---|
> | `font="楷书和行书"` + `conflicting_values` | `invalid`（含成对 `invalid_value`） |
> | `font="楷书"` + `conflicting_values` | `conflict`（仅 `conflicting_values`） |
>
> 因此本集受影响的冲突样本是 **9 条**（候选原值为冲突短语者），非全部 22 条。
> §3.2 / §4.1 与实现的不一致仍然成立，缺陷依然真实，只是范围收窄。

**最小修复方案（约 4 行，供上游参考，本次未应用）**

```python
# parsing/parse_requirement_v2.py::_collect_errors
for field, supported in (("font", FONTS), ("duration_minutes", DURATIONS)):
    raw = candidate.get(field)
    value = values[field]
    if raw is None:
        continue
    # 该字段已判定为冲突时，不再补非法值，避免 conflict 被降级为 invalid
    if any(i["field"] == field and i["type"] == "conflicting_values" for i in errors):
        continue
    if value is None or value not in supported:
        add("invalid_value", field, raw)
```

修复后需同步调整的测试：`test_parse_v2.py` 中依赖冲突样本最终状态的断言。

## D02 · 「想练楷书，但不要练楷书」在 v2 如何处理

| 项 | 内容 |
|---|---|
| 背景 | v1 用 `style` + `exclusions` 两个字段表达「要什么/排除什么」；v2 已删除 `exclusions`。任务说明 §4.3 明确要求该边界「仍涉及语义矛盾，应登记裁决」。 |
| 候选解释 A | 视为 `font` 字段的**自我矛盾** → `conflicting_values`。 |
| 候选解释 B | 视为非法值 → `invalid_value`。 |
| 候选解释 C | 视为缺失（用户未表达有效书体）→ `missing_field`。 |
| **裁决** | **采用 A 的语义方向，但状态最终落 `invalid`**：按 D01 所述实现行为，冲突字段会被同时补上 `invalid_value`。 |
| 落地 | 样本 `V2-D094`（dev）、`V2-S115`（sealed），`expected_model_errors` 含 `conflicting_values/font` 与 `invalid_value/font`，`status=invalid`。 |
| 备注 | v1 的 `plan_gate=block` 结论**不适用于 v2**，不得迁移。 |

## D03 · 区间、约数、模糊时长不得取端点

| 项 | 内容 |
|---|---|
| 边界 | `大概20分钟左右`、`15到20分钟`、`一会儿`、`一小会儿`。 |
| **裁决** | 一律**不取端点、不落最接近档位**：有明确数值但为区间/约数 → 记 `invalid_value`；完全无数值的模糊表达（「一会儿」）→ 记 `missing_field`。 |
| 依据 | 任务说明 §3.2「不能静默映射到最接近档位」；W04-1 探针判据「区间/约数不取端点」已用单元测试固化。 |
| 落地 | `V2-D085`（大概20分钟左右 → invalid）、`V2-D086`（15到20分钟 → invalid）、`V2-V083` / `V2-S105`（一会儿 → missing）。 |
| 备注 | `15到20分钟` 虽含合法值 15，也**不得**直接采用。 |

## D04 · 并列项中含非法值时的归类（非法 vs 冲突）

| 项 | 内容 |
|---|---|
| 边界 | `楷书和行书`（两个都合法）vs `楷书和草书`（一个非法）、`行书和行楷哪个都行`（两个都合法）。 |
| **裁决** | 并列项**全部合法** → `conflicting_values`；并列项**含任一非法值** → 整体记 `invalid_value`（不拆成「非法+冲突」两条）。 |
| 落地 | `V2-D087`（楷书和草书 → invalid_value）。 |
| 备注 | 实现上含非法项时原值仍不为合法枚举，`conflicting_values` 是否并存取决于模型是否报冲突；本集按模型报了冲突标注，同时保留本地补的 `invalid_value`。 |
